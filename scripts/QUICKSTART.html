8-pillar automated RTL verification — lint to GLS. All tools run on dada-ser; you edit and view results from Windows via VSCode Remote-SSH over Tailscale.

🖥️ Setup — Windows + VSCode → dada-ser via Tailscale

Architecture: Your Windows laptop is just an editor. All EDA tools (Verilator, Yosys, OpenSTA, Icarus, SymbiYosys) live on dada-ser. VSCode Remote-SSH tunnels over Tailscale so you get a native IDE feel with zero local installs.

Step 1 — Install Tailscale on Windows

1

Download and install Tailscale from tailscale.com/download/windows

Sign in with the same account used on dada-ser (SachinGoolla@).

After login, open a PowerShell and verify dada-ser is visible:

tailscale status

You should see 100.125.23.67 dada-ser in the list.

Step 2 — Install VSCode + Remote-SSH extension

2

Install VSCode, then open the Extensions panel (Ctrl+Shift+X) and install:

Remote - SSH (ms-vscode-remote.remote-ssh) Remote - SSH: Editing Configuration Files

Optional but recommended:

SystemVerilog - Language Support Python

Step 3 — Add dada-ser to SSH config

3

Open a PowerShell and create/edit %USERPROFILE%\.ssh\config:

Host dada-ser
    HostName 100.125.23.67
    User dada
    ForwardAgent yes

Using the Tailscale IP directly is most reliable. The hostname dada-ser also works if MagicDNS is enabled in your Tailscale admin.

If you use an SSH key, add: IdentityFile ~/.ssh/id_ed25519

Step 4 — Connect VSCode to dada-ser

4

Press F1 → type Remote-SSH: Connect to Host → select dada-ser.

A new VSCode window opens connected to the server. In the integrated terminal:

cd /home/dada/silicon_portfolio
ls

Then open the folder: File → Open Folder → /home/dada/silicon_portfolio

Step 5 — One-time environment setup (run once on dada-ser)

5

In the VSCode terminal (which is already SSH'd into dada-ser):

bash /home/dada/silicon_portfolio/scripts/setup_env.sh

This sets up the Python venv with cocotb, adds pillar to PATH, and writes a welcome banner. Re-open the terminal after it completes.

✓ You're in. The VSCode terminal is now a full EDA shell. All pillar commands run directly — no extra steps.

🚀 Run Your First Verification

pillar --top mod1000            # all 8 pillars, ~2 min
pillar --top mod1000 --step lint   # just P1 lint+CDC
pillar --top mod1000 --step sta    # just P8 STA+GLS

Soft-fail: all pillars run even if one fails. Full summary printed at the end.

❓ Troubleshooting

Cannot connect — "Connection refused" or timeout

1. Check Tailscale is running on both machines: Windows system tray icon should be green.

2. Verify dada-ser is reachable from PowerShell:

ping 100.125.23.67

3. If ping works but SSH doesn't, check sshd is running on dada-ser:

sudo systemctl status ssh

4. Confirm your Windows SSH config has the right IP (100.125.23.67) and username (dada).

SSH asks for password every time

Set up a key pair. In Windows PowerShell:

ssh-keygen -t ed25519 -C "windows-laptop"
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh dada@100.125.23.67 "cat >> ~/.ssh/authorized_keys"
VSCode says "Remote-SSH host key changed"

dada-ser's host key may have changed (OS reinstall, etc). Remove the old key from Windows:

ssh-keygen -R 100.125.23.67

Then reconnect — you'll be prompted to accept the new host key once.

pillar command not found after setup

Re-open the terminal (the venv and PATH are set in ~/.bashrc). Or activate manually:

source ~/.bashrc
P2 Formal: ModuleNotFoundError: No module named 'click' 
pip3 install click
P7 LEC always WARN (never PASS)

Expected for sky130 — Yosys equiv can't normalize PDK black-box cells. WARN = inconclusive, not a failure. LEC PASS only appears for generic/nangate netlists. Use Cadence Conformal for sign-off LEC.

P8 GLS SKIP — no cell Verilog models

GLS needs sky130 behavioral Verilog. On dada-ser the symlinks are already in place:

ls -la /home/dada/silicon_portfolio/lib/*.v

If missing (fresh clone), re-run setup or symlink manually:

PDK=/home/dada/pdks/volare/sky130/versions/0fe599b2afb6708d281543108caf8310912f54af/sky130A/libs.ref/sky130_fd_sc_hd/verilog
ln -s $PDK/primitives.v lib/sky130_primitives.v
ln -s $PDK/sky130_fd_sc_hd.v lib/sky130_fd_sc_hd.v
P6 Synthesis SKIP — no .lib files

On dada-ser the sky130 .lib symlinks should already be in lib/. If not:

PDK=/home/dada/pdks/volare/sky130/versions/0fe599b2afb6708d281543108caf8310912f54af/sky130B/libs.ref/sky130_fd_sc_hd/lib
ln -s $PDK/sky130_fd_sc_hd__tt_025C_1v80.lib lib/
ln -s $PDK/sky130_fd_sc_hd__ss_n40C_1v28.lib lib/
ln -s $PDK/sky130_fd_sc_hd__ff_n40C_1v76.lib lib/
STA shows VIOLATED after synthesis

Increase -period in your .sdc (sky130 max ~100 MHz at combinational depth ~5), or pipeline the critical path. Check logs/sta_*.log for the failing path endpoints.
