# rv32i_soc — Engineering Report: Composing a Real SoC, an Adversarial Review That Found a Vacuous Proof, and a Confirmed Gate-Level Simulation Scale Wall

_Companion to `STATUS.md`. Phase 1, Step 4 (final step) of the RISC-V SoC roadmap: composing `rv32i_core`, `fpu_axi_periph`, and `uart_axi_periph` behind a new address decoder into a real, running RISC-V SoC — one master, three memory-mapped slaves, a synthesized instruction ROM holding an actual assembled program. The decoder is the only genuinely new RTL this step; everything else is flat-copy composition of three already-independently-verified IPs, following this portfolio's established pattern. An adversarial review of that composition caught two real bugs in the decoder — one of them a formal proof that passed while proving nothing — both fixed and re-verified. The composition itself works end-to-end on real hardware-equivalent simulation. What it does **not** achieve is a clean 9/9 pillar sweep: gate-level simulation on the resulting ~68K-cell netlist does not converge within this flow's wall-clock budget, a genuine, confirmed scale limitation this report documents honestly rather than routes around._

## Situation

Steps 1–3 built the pieces this step composes: `uart_axi_periph` (Step 1) proved the composition pattern, `rv32i_core` (Step 2) is a formally-checkpointed 5-stage pipeline with its own AXI4-Lite master, and `scripts/rv32i_asm.py` (Step 3) is a general-purpose RV32I assembler with 102 oracle tests but, at the time Step 4 began, had never been exercised against real downstream tooling — its `--format rom` output had never actually been compiled by anything. Step 4 is the payoff: one master (the core), three memory-mapped slaves (a data RAM, the UART peripheral, the FPU peripheral), and a real assembled program that exercises all of it. The user specified RAM size (256 words / 1KB) and confirmed push timing (wait until this step lands, then push Phase 1 as one coherent unit) via two clarifying questions; everything else followed the roadmap's own standing checkpoint discipline — write RTL, prove it standalone, only then compose upward.

## Task

Design the address decoder (the only new module), formally verify it standalone before touching the top-level composition, flat-copy the three proven IPs plus the decoder into `rv32i_soc.sv`, write and independently cross-check a real test program (FPU compute, RAM round-trip, UART TX/RX, a deliberate DECERR touch), build the verification harness, and take the whole thing through all 9 pillars.

## Action

### The decoder: registered select latches, a DECERR generator, and a scope assumption read directly out of the LSU's own FSM

`rv32i_addr_decoder` demuxes the core's single AXI4-Lite master port to three slaves using registered select latches — captured at the AW/AR handshake, held through B/R via `wbusy_q`/`wsel_q` (write) and `rbusy_q`/`rsel_q` (read) — plus a self-contained DECERR response generator for unmapped addresses (no real slave exists to answer one, so the decoder buffers its own AW/W pair and commits a synthesized `2'b11` response, mirroring `axi_lite_slave.sv`'s own `aw_pend_q`/`w_pend_q`/commit pattern). The design assumes a single-outstanding master — justified not by convention but by actually reading `rv32i_lsu.sv`'s FSM (`S_IDLE → S_WRITE/S_READ_ADDR → ... → S_IDLE`), which structurally cannot issue a new AW/AR before the prior B/R completes — and states that assumption explicitly as a formal `assume()`, not an unstated design note.

### Two real BMC counterexamples during the decoder's own proof

Boolector caught a real bug on the first BMC run: `bvalid_o`/`rvalid_o` were originally muxed through the *live pre-latch* decode signal (`wsel_active`), which let a real slave's own free-running `bvalid_i` leak into the decoder's output the instant `awaddr_i` happened to point at that slave's page — even with no write actually in flight (`wbusy_q == 0`). Fixed by gating the B/R response muxes strictly on the *latched* `wbusy_q`/`wsel_q`, matching the real timing guarantee every proven slave already provides (its own B/R response is registered at least one cycle after commit). A second counterexample after that fix exposed the proof exploring a master behavior no real single-outstanding master produces — a new AW asserted while a DECERR write was still pending — closed by the `assume(!(wbusy_q && awvalid_i))` scope assumption described above. After both fixes, BMC depth 20 passed clean and stayed clean through every subsequent edit.

### Program authoring: an independent decode-check, and a transcription bug that was mine, not the assembler's

`program.s` exercises an FPU FADD(1.0, 1.0)=2.0 launch-and-poll sequence, a RAM store/load round-trip through the decoder, a UART TX byte with RX loopback, and a deliberate touch of an unmapped address to prove DECERR propagates all the way back through the full stack (the LSU ignores `bresp_i`/`rresp_i` by design, so the core is expected to keep running normally afterward). Every instruction was independently cross-checked with a disassembler written separately from the assembler's own bit-manipulation code — the same discipline `rv32i_core`'s Step 2 harness established. That check itself caught a bug, but the bug was mine: hand-transcribing the assembled word list from a terminal print into a Python array for the cross-check, I mistyped one word (`0xFE078CE3` instead of `0xFE048CE3`), which looked exactly like a wrong-register branch bug. Redoing the check by reading the assembled output directly from disk instead of retyping it showed the assembler had been correct all along.

### `format_rom()`'s first real use found three real bugs in Step 3's own deliverable

Step 3 shipped `rv32i_asm.py --format rom` with 102 passing oracle tests, but none of them had ever fed the generated Verilog through an actual toolchain. This step's first real invocation immediately found three bugs no oracle test could have caught, because they're properties of the *generated file*, not the assembler's encoding logic: Icarus rejects a part-select used directly as a `case` expression (fixed with an intermediate `rom_idx` wire, the same idiom already established in `rv32i_lsu.sv`); the generated file had no trailing newline (harmless to tools that don't care, but inconsistent with every other generated/hand-written file in this repo); and — found later, during this step's own close-out, prompted by the fact the fix above had never been applied to `format_words()`, the sibling formatter — `format_words()` had the identical missing-trailing-newline gap. Both formatters and `main()`'s own file-write path were fixed together (the write path no longer double-appends a newline now that both formatters guarantee their own), and two new regression tests (`test_format_rom_compiles_under_iverilog`, `test_format_rom_lints_clean_under_verilator`) close the gap that let the first three slip through: an oracle test proves encoding correctness, not that the tool downstream of it will accept the output.

### An adversarial review, degraded by a session limit mid-run, still found two real bugs

Before hardening the decoder further, a 3-dimension adversarial review (decoder-protocol, soc-wiring, program-correctness; each finding independently re-verified) was launched. It hit this session's own usage limit mid-flight — 16 of 18 planned agent calls failed — leaving only 2 of 3 dimensions complete and the automated verification stage essentially unable to run. The workflow's own summary reported `confirmed: []`, which is not the same claim as "review found nothing": it reflects failed verification infrastructure, not a clean bill of health. Recognizing that distinction mattered — reading the raw per-agent transcript directly (rather than trusting either the empty summary or the raw unverified claims) surfaced two genuinely real, high-severity findings, both independently confirmed by reading the current source myself:

1. **The formal proof was vacuous.** The decoder's `$onehot0`-over-mutually-exclusive-comparisons properties were true by construction of the RTL's own case statement, regardless of whether the address-to-slave *mapping* itself was correct — a future edit that swapped `RAM_PAGE` and `UART_PAGE` together (self-consistently, but wrong) would have sailed through the exact same proof. Fixed by adding a second property block that hardcodes the intended mapping as literal 20-bit constants (`20'h00000`, `20'h00001`, `20'h00002`) independent of the RTL's own `RAM_PAGE`/`UART_PAGE`/`FPU_PAGE` localparams — the property block visible at lines 454–488 of the final RTL.
2. **A real address-aliasing gap.** The original decoder compared only `awaddr_i[19:12]` (8 bits, not the full 20-bit page field) against the page constants and passed the low address bits straight through with no bounds check. Both halves of that were real: any address `addr[31:20]` different but `addr[19:12]` matching would alias onto the same slave every 1MB, and any in-page address past a slave's real (narrower-than-4KB) width silently landed on that slave's live registers with an `OKAY` response instead of `DECERR`. Fixed by decoding the full 20-bit page field and adding an explicit `*_in_bounds` check per slave, gating every page match on it (RTL header comment at `rv32i_addr_decoder.sv:8–24` documents the fix and the exact bug it replaced).

Both fixes are covered by new, non-tautological formal properties and three new `cover()` targets proving the in-page-out-of-bounds DECERR path is genuinely reachable, not eliminated by construction.

### Two synthesis-boundary GLS elaboration failures, both fixed

Getting P8 GLS to even *compile* against the synthesized netlist surfaced two structural facts about what survives Yosys synthesis, neither obvious in advance and both confirmed by real elaboration errors, not guessed:

- **No parameters survive.** `tb_rv32i_soc.sv`'s original `#(.CLK_FREQ(1600), .BAUD_RATE(100))` instantiation override failed with `parameter CLK_FREQ not found in tb_rv32i_soc.u_dut` — whatever value was active at synthesis time is permanently baked in, and a testbench-level override at GLS-mode instantiation is a hard elaboration error, not a no-op. Fixed by making `rv32i_soc.sv`'s own module defaults the fast-sim values directly, so every pillar sees identical timing with no per-pillar override needed.
- **No internal (non-port) hierarchy survives.** After fixing the above, `Unable to bind wire/reg/memory u_dut.u_ram.reg_q[...]` — Yosys decomposes an unpacked register-file array into individual gate-level flip-flop cells with no surviving hierarchical name. Only ports remain observable. Fixed with an `` `ifdef GLS `` split in `tb_rv32i_soc.sv`: RTL-mode keeps the full hierarchical golden-value check against `u_ram.reg_q`; GLS-mode instead runs a fixed cycle budget and checks only that `uart_tx_o` toggled — a port-level, synthesis-survivable signal that's only reachable if the CPU genuinely executed the FPU-compute-then-poll sequence and the RAM round-trip correctly at gate level, in the same spirit as `uart_axi_periph`'s own precedent for this exact class of problem.

### GLS does not converge — confirmed, not assumed, and not worked around

With both elaboration errors fixed, the GLS *simulation itself* does not complete within this flow's 120-second wall-clock budget. This was run down methodically, not assumed:

- Direct `ps` monitoring during a manual run showed 100% CPU, process state `R` — genuinely computing, not deadlocked.
- Reducing the GLS-mode cycle target to 3 clock cycles (far below the canonical 2000) still failed to complete within 60 seconds of manual testing.
- Removing `$dumpvars` entirely did not fix it, ruling out FST/VCD dump overhead as the sole bottleneck.
- The final `--force` sweep's own log confirms it independently of all manual diagnosis — `logs/gls_rv32i_soc.log`'s last line, verbatim, is `GLS TIMEOUT: exceeded 120s wall-clock limit`. **This is the raw log, and it matters that it's quoted directly**: the pillar dashboard's summary panel prints the generic template text "GLS FAIL — functional mismatch between RTL and gate simulation" for *any* GLS failure, timeout or not. That template text is not evidence of an actual RTL/gate divergence, and this report does not repeat it as if it were.

Two structural facts localize the problem to *composition scale*, not a defect introduced this step: `rv32i_core` and `fpu_top` (inside `fpu_axi_periph`) each already passed GLS individually, at a small fraction of this design's size. The composed netlist is 67,984 cells / 20,796 flip-flops, against `rv32i_core`'s own standalone 322 cells / 1,601 flip-flops — roughly 211x the cell count and 13x the flip-flop count, the difference being that this netlist also carries the entirety of `fpu_axi_periph` and `uart_axi_periph`, not just the core. The leading hypothesis is an X-propagation storm during/after reset (sky130 std-cell flip-flops have no defined power-on value, a known GLS risk this portfolio already tracks) interacting badly with interpreted, zero-delay Icarus simulation at this scale — but this was not isolated with certainty; distinguishing "genuine non-convergence" from "correct but pathologically slow for an interpreted simulator at this cell count" would need waveform-level analysis on a simulation that, by definition, doesn't produce waveforms in bounded time.

Two options were available once this was confirmed real: extend `p8_sta_gls.py` (shared across every IP in this portfolio) with a distinct SKIP-on-timeout classification, or document a real, honest FAIL for this IP specifically. The first was rejected — `p8_sta_gls.py` gates every other IP's GLS pillar too, and a change that makes GLS timeouts tolerable portfolio-wide is a strictly worse engineering statement than one IP's honest FAIL, for a change whose only real beneficiary would be this dashboard's color. This report takes the second option: P8 is FAIL, GLS specifically, for a confirmed and explained reason, with STA (the other half of P8) passing at TT and the standard advisory violation at SS. No `pillar.py`/`p8_sta_gls.py` code was touched.

## Result

- **7/9 PASS, 1 documented WARN, 1 documented FAIL** — the first step in this roadmap not to reach the "N/9 PASS, 1 WARN" shape every prior IP did. That's a real, not a stretched, outcome.
- **Composition works end-to-end**: the real assembled program (FPU FADD, RAM round-trip, UART TX+RX loopback, a DECERR touch) runs to completion and all golden values match, confirmed on two independent RTL-level vehicles (Verilator P4, cocotb/Icarus P3) plus the decoder's own standalone formal proof.
- **PPA**: 67,984 cells, sky130. TT +9.889 ns MET at the 20 MHz target. SS −348.991 ns is the standard pre-layout advisory-only violation — and it is *numerically identical* to `rv32i_core`'s own standalone SS figure (also −348.991 ns). Tracing the actual STA critical path (`u_core/_2909_ → u_core/u_hazard/... → u_core/_3188_`) confirms it: the binding path runs entirely through the core's own hazard-forwarding logic, unchanged by composing three peripherals and a decoder around it. The SoC added no new critical path.
- **Coverage is honestly lower than any prior IP in this portfolio** (73.0% line vs. `rv32i_core`'s 95.0%) — not a regression in test quality, but an expected consequence of scale: one directed test program exercises the FPU's add path and one UART byte in each direction, leaving most of the UART TX FIFO's depth, the FPU's other opcodes, and several ALU shift/logic `default:` arms untouched. Advisory only (no `--coverage-threshold` set this run); a real improvement path exists (see Open Items) but was out of this step's scope.
- **LEC**: WARN, the same k-induction-non-convergence class documented for every other sequential IP in this portfolio (`fpu_top`, `uart_ctrl`, `axi_lite_slave`), cross-verified by P2 Formal + P8's own passing STA and (when it completes) GLS.
- **GLS**: FAIL — TIMEOUT, confirmed via the raw log and independent manual diagnosis, not a functional RTL/gate mismatch. See Open Items.

## Skills Demonstrated

- **Checkpoint-discipline composition** — the one genuinely new module (the decoder) proven standalone before any composition; the three flat-copied IPs were each already proven in their own prior steps.
- **Adversarial-review triage under degraded infrastructure** — distinguishing "verification failed to run" from "verification found nothing," and independently re-confirming raw candidate findings against current source rather than trusting either extreme.
- **Formal-proof honesty** — recognizing and closing a specific, well-understood failure mode (a property provable from the RTL's own internal self-consistency, independent of whether the RTL's actual intent is correct) rather than treating a passing BMC run as sufficient on its own.
- **Root-cause discipline under time pressure** — running a genuine scale limitation to ground with multiple independent confirmations before either accepting a shortcut (weakening shared pillar infrastructure) or accepting an unproven guess (assuming "functional mismatch" because that's what the dashboard's template text said).
- **Toolchain-divergence navigation** — reconciling Icarus's explicit-cast requirement for enum-typed ternary assignments against Yosys's rejection of that same cast syntax by removing the divergence's root cause (enum-typed intermediate signals) instead of chasing per-tool workarounds.
- **Honest reporting under an incomplete result** — this is the first report in this roadmap that isn't "N/9 PASS, 1 WARN," and it says so directly rather than reframing the outcome to match the pattern of the prior three.

## Open Items — What I'd Do Next

The GLS timeout is the real open item. Two directions are worth trying, neither attempted here: (1) a targeted waveform-free bisection — instrument the netlist's reset-fanout structurally (not via simulation) to check whether an unreasonably large fraction of the 20,796 flip-flops share a single reset fanout tree that could plausibly explain a combinational X-storm, before assuming interpreted-simulator scaling is the whole story; (2) if it is purely a scale/performance ceiling rather than non-convergence, a commercial or compiled (not interpreted) gate-level simulator would likely resolve it outright — worth a note for whenever this portfolio has access to one. Coverage's gap is addressable directly: a second test program exercising the UART's fuller FIFO depth and a broader FPU opcode set would close most of the 27-point line-coverage gap versus `rv32i_core` without any RTL change. P7's LEC WARN is the same open item every sequential IP in this portfolio carries — Cadence Conformal or Synopsys Formality territory, not something this toolchain resolves. This closes Phase 1 of the 4-phase roadmap (RISC-V SoC integration); Phase 2 is the AXI4-Stream/systolic MAC tile.
